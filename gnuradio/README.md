# GNU Radio examples for the PlutoSky R2

QPSK file and live-video transmission with GNU Radio 3.10 (gr-iio / PlutoSDR blocks). The step-by-step guide is [docs/GNU-Radio-Video-Transmission.md](../docs/GNU-Radio-Video-Transmission.md) ([PDF](../docs/GNU-Radio-Video-Transmission.pdf)).

| Folder | Flowgraph | Hardware | What it does |
|---|---|---|---|
| `01_Software-Loopback/` | `05_QPSK_File_Simulation.grc` | none | Sends `sample.mp4` through a simulated QPSK channel and writes `received.mp4` |
| `02_Single-Board-RF-Loopback/` | `08_QPSK_File_Loopback_R2.grc` | 1 PlutoSky R2, antennas on TX1 and RX1 | Same file transfer over the air on one board |
| `03_Two-PC-File-Transfer/TX/` | `TX_PC_A.grc` | PC A + PlutoSky R2-A | File transmitter |
| `03_Two-PC-File-Transfer/RX/` | `RX_PC_B.grc` | PC B + PlutoSky R2-B | File receiver with CRC check |
| `04_Two-PC-Live-Camera/TX/` | `TX_CAMERA_PC_A.grc` | PC A + PlutoSky R2-A + camera | Live camera (JPEG) transmitter |
| `04_Two-PC-Live-Camera/RX/` | `RX_VIDEO_PC_B.grc` | PC B + PlutoSky R2-B | Live video receiver and player |

The `.py` files next to the two-PC flowgraphs are the Python code generated by GNU Radio Companion and their embedded Python blocks; they run without opening GRC.

Notes:

- The test video is not included. Use any MP4 file and name it `sample.mp4`, or change `file_name`. The received file is written to `received.mp4` (`output_file_name`). Both paths are relative to the folder the flowgraph runs from.
- The default device URI is `ip:192.168.2.1`. Change `tx_uri` / `rx_uri` if your board has another address.
- The flowgraphs transmit at 2 GHz. Use antennas or attenuators suited to the band and observe local radio regulations.
